# AGNES Family OS UI v1 Design

Date: 2026-09-05
Status: Approved product direction translated into repository design
Repository: `k25vsgvkmw-code/agnes-tv`

## 1. Goal

Add the first production presentation layer to the greenfield AGNES Core without inheriting the legacy AGNES TV UI. The result is one coherent Family Operating System shell for desktop, tablet and mobile, with Home, Today, Family and Explore as the primary navigation model and AGNES AI as a global contextual layer.

This UI v1 is presentation-first and provider-independent. It must render useful household context even when optional external providers are unavailable, and it must not move provider-specific SDK logic into the presentation layer.

## 2. Scope

UI v1 includes:

- global shell and design tokens;
- compact top bar with date/time and weather summary slot;
- primary navigation: Home, Today, Family, Explore;
- global AGNES voice/assistant control;
- Home family-stage view;
- Today timeline and attention state;
- Family member overview;
- Explore hub containing consistent views for Kids, Cooking, Travel, Tonight, Health, Calendar, Never-Miss, Shop, Finance, Car, Smart Home, Pets, Music, Learning, Services, Translator and Memories;
- responsive desktop/tablet/mobile behavior;
- server-side Fastify route registration for the presentation entry point;
- deterministic presentation snapshot contract so later adapters can replace demo/fallback data without changing the view structure.

Out of scope for this first presentation slice:

- direct calls from browser code to Google, Spotify, travel, weather, health or smart-home providers;
- provider authentication flows;
- persistent UI preferences;
- production 3D assets or private household photographs;
- replacing the existing Core domain contracts.

## 3. Architecture

The presentation subsystem lives under `src/presentation/web/` and depends inward on typed presentation contracts only. Core domain and integration modules do not depend on presentation code.

The Fastify server registers `registerAgnesWebRoutes()` in addition to existing health routes. The web route returns a self-contained HTML document generated by the presentation renderer. CSS and browser behavior are emitted from focused TypeScript modules so the existing TypeScript build remains the only build pipeline and no new runtime dependency is required.

A `FamilyOsSnapshot` is the sole input to the renderer. It is deliberately provider-neutral and contains only view-ready data: household label, current context, members, timeline, attention item, weather summary, and Explore module cards. Later application adapters can construct the same snapshot from canonical household, calendar, notification, weather and integration data.

## 4. Information Architecture

Primary navigation contains only four product destinations:

1. Home — the household now.
2. Today — current and upcoming day flow.
3. Family — people and their current state.
4. Explore — lifestyle and management modules.

AGNES AI is global and never becomes a fifth disconnected mini-app.

## 5. Visual System

The interface uses a single cinematic family-oriented visual system:

- deep/slate purple foundation;
- pastel violet, sea-blue and warm-earth accents;
- translucent glass surfaces used sparingly;
- atmospheric gradients and depth rather than black SaaS panels;
- large spatial hero area on Home;
- compact information density above the fold;
- no full-size weather dashboard on Home;
- no page-specific navigation redesigns;
- rounded responsive surfaces with clear focus states;
- touch targets at least 44 CSS pixels on touch layouts.

The Home hero is the visual anchor. It should feel like a family stage rather than a widget grid. The Travel view reserves the majority of its hero for imagery when real destination media is connected later.

## 6. Responsive Rules

Desktop:

- compact top bar;
- floating left rail;
- wide Home family stage plus context panel;
- multi-column Explore cards.

Tablet:

- reduced rail footprint;
- two-column content where useful;
- touch-first controls.

Mobile:

- bottom navigation;
- vertical full-width cards;
- one-handed primary actions;
- no compressed desktop rail.

## 7. Interaction Model

Navigation is client-side within the rendered shell using `data-view` controls. Only one primary view is visible at a time. Explore module cards open module detail surfaces inside the same shell and provide a consistent Back action.

The AGNES control opens a contextual assistant panel. In UI v1 this is a deterministic presentation layer with suggested prompts; model orchestration remains behind the existing intelligence boundary.

Keyboard interaction must support navigation buttons and Escape to close overlays/module details.

## 8. Presentation Snapshot

`FamilyOsSnapshot` contains:

- `householdName`
- `locale`
- `timezone`
- `nowLabel`
- `weather` summary
- `members[]`
- `attention`
- `timeline[]`
- `exploreModules[]`

No personally identifying household defaults are committed to the public repository. The fallback snapshot uses generic role labels and can later be replaced by a real application adapter.

## 9. Server Integration

`src/app/server.ts` registers the web presentation route after health routes. `/health` remains unchanged.

Routes:

- `GET /` — AGNES Family OS shell.
- `GET /ui/snapshot` — provider-neutral snapshot JSON for diagnostics and future progressive enhancement.

Route registration accepts an optional snapshot factory for tests and future application composition.

## 10. Testing

Unit tests cover:

- snapshot structure and module completeness;
- renderer output contains the required primary navigation, main views, assistant control and Explore modules;
- Fastify route registration serves HTML at `/` and JSON at `/ui/snapshot`;
- existing `/health` behavior remains unaffected.

Tests follow existing Vitest/Fastify injection conventions and require no browser runtime.

## 11. Security and Privacy

The public repository must not embed private family names, health data, schedules, addresses or credentials in fallback presentation data. Presentation rendering escapes externally supplied text before inserting it into HTML.

No provider tokens or secrets are exposed to the browser.

## 12. Completion Criteria

UI v1 is complete when:

- the new presentation routes compile under the existing strict TypeScript configuration;
- all existing Core tests remain green;
- presentation tests are green;
- lint, build, formatting and CI pass;
- the shell provides consistent Home, Today, Family, Explore and module-detail navigation on one responsive visual system;
- no legacy UI dependency or provider-specific browser coupling has been introduced.
